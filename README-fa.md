# پروکسی شخصی HTTP برای Railway

این پروژه یک پراکسی HTTP با پشتیبانی از HTTPS مقصدها (از طریق CONNECT) و احراز هویت می‌سازد. برای آن‌که کلید/رمز از طریق اینترنت عمومی بی‌محافظ منتقل نشود، این نمونه به‌تنهایی **TLS بین کلاینت و خود پراکسی فعال نمی‌کند**. جزئیات این تفاوت در پاسخ چت توضیح داده شده است.

## فایل‌های پروژه
- `Dockerfile`
- `tinyproxy.conf.template`
- `start.sh`

## مراحل Railway
1. این پوشه را در یک مخزن GitHub جدید قرار دهید.
2. در Railway یک پروژه بسازید و Deploy from GitHub Repo را انتخاب کنید.
3. در Settings / Variables دو متغیر تنظیم کنید:
   - `PROXY_USER`: فقط حروف انگلیسی و عدد، `_` یا `-`
   - `PROXY_PASSWORD`: رمز تصادفی قوی، فقط حروف انگلیسی و عدد، `_` یا `-` (ترجیحاً حداقل 32 کاراکتر)
4. منتظر بمانید Deploy سالم شود.
5. در Settings / Networking / TCP Proxy پورت داخلی `8888` را اضافه کنید.
6. Railway یک hostname و پورت عمومی می‌دهد. این دو مقدار را در مثال پایتون به کار ببرید.

## تست پایتون
```python
import requests

proxy = "http://PROXY_USER:PROXY_PASSWORD@HOST.proxy.rlwy.net:PORT"
proxies = {"http": proxy, "https": proxy}

r = requests.get(
    "https://api.ipify.org?format=json",
    proxies=proxies,
    timeout=20,
)
print(r.status_code, r.text)
```
مقادیر بالا نمونه‌اند؛ با داده‌هایی که خود Railway می‌دهد جایگزینشان کنید. در صورت موفقیت، پاسخ باید IP خروجی سرویس را نشان دهد.

## امنیت
- رمز واقعی را در کد GitHub قرار ندهید؛ فقط در Railway Variables ذخیره کنید.
- پراکسی را بدون احراز هویت در اینترنت عمومی منتشر نکنید.
- این نمونه، ارتباط کلاینت تا خود پراکسی را TLS نمی‌کند؛ HTTPS مقصد پس از تونل CONNECT رمزنگاری می‌شود، اما Basic Auth روی اتصال کلاینت تا پراکسی ممکن است در معرض شنود باشد. روی شبکه نامطمئن استفاده نکنید مگر این‌که TLS برای خود نقطهٔ اتصال پراکسی نیز جداگانه پیکربندی شود.
